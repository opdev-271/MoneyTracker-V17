# Money Tracker

Android app (Java, MVVM, Room) for tracking income and expenses across multiple
accounts with different currencies, matching the reference design you shared.

## Opening the project

1. Open **Android Studio** (Koala/2024.1 or newer recommended — the project
   targets Java 17 and Gradle 8.7).
2. Choose **File ▸ Open** and select this folder
   (`tracker android app`).
3. Let Gradle sync. On first sync Android Studio will:
   - fill in `local.properties` with your SDK path automatically, and
   - download the Gradle 8.7 distribution + generate `gradle/wrapper/gradle-wrapper.jar`
     if it's missing (this repo only ships the wrapper *scripts*, not the
     binary jar — Studio regenerates it on sync, or you can run `gradle wrapper`
     once yourself if you have a system Gradle install).
4. Run the `app` configuration on an emulator or device (min SDK 24).

No backend/API keys are needed — everything is stored locally in a Room
(SQLite) database on the device.

## What's included

- **Home** — balance card for the active account, quick actions (Send / Add
  funds / Request / More), recent transactions list. Tap the account name to
  switch accounts if you have more than one; tap the eye icon to hide/show
  the balance.
- **Add transaction** — opened from the quick actions; expense/income toggle,
  amount, account picker, category picker, date picker, description.
- **Wallet** — list of accounts with live balances; tap `+` to add an
  account, tap an account to edit or delete it.
- **Analytics** — income vs. expense totals and a pie chart of expenses by
  category, switchable between week/month/year.
- **Settings** — switch the app language between English and Czech
  independently of the phone's system language, and hide balances on Home.
- **Categories** — opened from Settings; the full category list split into
  expense and income, where each one's name, icon, color and type can be
  changed, new ones added and unused ones deleted. Deleting is non-destructive
  (transactions keep their amounts and just go uncategorized), and the
  confirmation says how many transactions that will affect.

## Architecture

- **MVVM**: `ui/<feature>/XxxFragment` + `XxxViewModel` (`AndroidViewModel`,
  so each ViewModel reaches its repositories via `MoneyTrackerApp`).
- **Room**: entities/DAOs/database in `data/`; `AppDatabase` seeds a default
  "Cash" account and a starter set of categories the first time the app runs.
- **Repositories** (`data/repository`) wrap the DAOs and move writes onto a
  background executor (`util/AppExecutors`).
- Seeded accounts/categories are stored under a stable key (e.g.
  `category_food`) instead of literal text so their label can be
  re-localized after a language switch — see `util/DisplayNameResolver`.
  Anything you create yourself is stored as literal text and shown as-is, and so
  is anything you rename — editing a seeded category replaces its key with the
  label you typed, which is why lists sort on the *resolved* name
  (`util/CategorySorter`) rather than in SQL.
- The light theme is layered rather than flat. The page is a warm off-white
  (`background`) carrying a tiled grain bitmap (`@drawable/bg_page`, tile
  generated by `tools/gen_texture_tile.py`); cards are white (`surface`) with a
  whisper of gradient and **no outline** — `card_stroke` is transparent, so
  depth comes from the tone difference plus the elevation shadow. The dark
  theme keeps `background == surface`, so there `card_stroke` is a real hairline
  and every gradient collapses to a flat color; it renders as it always did.
  Consequence worth knowing: a white card cannot sit on a white surface any
  more, so containers that hold cards use the page color (`bg_sheet`) and rows
  inside white dialogs use a tinted well (`bg_row_light`) instead.
- The bottom nav pill is real frosted glass, not a translucent fill.
  `ui/widget/GlassPanelView` sits behind it and samples the fragment container into a
  1/8-scale bitmap, box-blurs it and paints it back through a filtered `BitmapShader`;
  the pill's own drawable is only the translucent pane, sheen and specular rim on top.
  Two things this depends on: the pill's colors have to stay *very* transparent (at 70%
  white the blur is mathematically there and visually gone), and the capture target must
  be a sibling — pointing it at the root would recurse and would put the pill in its own
  reflection. Re-sampling is driven by scroll, layout and destination changes rather than
  every frame, so content that animates in place without scrolling will hold a stale
  sample until the next scroll.
- Dialogs blur the app behind them for real, via `FLAG_BLUR_BEHIND` in
  `DialogButtonStyler` — the one place Android offers a system-composited blur. It is
  API 31+ and the platform can refuse it at any time (low-RAM device, battery saver,
  the "disable window blurs" developer option), so it falls back to the plain dim.
- `android:elevation` on its own draws **nothing** in this app, which is why the
  hairlines were load-bearing for so long: every raised surface is a plain
  `LinearLayout` over a rounded `<shape>`, and `GradientDrawable` zeroes the
  outline alpha unless the drawable is opaque over its full bounds — which a
  rounded rectangle never is. `util/ElevationShadows` restores the outline (and
  warms the shadow color on API 28+). It has to be called on each inflated tree:
  Activities after `setContentView`, Fragments in `onViewCreated`, and RecyclerView
  ViewHolder constructors. **A new elevated view will silently have no shadow
  unless its tree goes through it.**

## Known simplifications (good next steps)

- Multi-currency accounts are each shown in their own currency; there's no
  currency-conversion layer, so Analytics totals sum raw amounts across all
  accounts regardless of currency.
- "Request" quick action currently opens the same income entry form as
  "Add funds" — there's no real request/invite flow.
- "See all" on Home and "More" don't navigate anywhere yet.
